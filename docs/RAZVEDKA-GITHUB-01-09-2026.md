Третий вывод — где Метида обязана давать не ноль. Context-fold прямо называет причину: дубли в агентном прогоне живут МЕЖДУ вызовами, а не внутри одного, и провайдерский кэш их не ловит, потому что работает по одинаковому префиксу, а у нас дубли идут вперемешку с новыми ходами. У Фемиды это ровно тот случай: детерминированные приборы выдают один и тот же текст по многу раз за прогон, карта дела и practice.md висят в контексте до конца сессии. Механизм — хэш-реестр блоков и маркер вместо повтора — обратим и ложится на обещание байт-в-байт без единой уступки.

Разметка по типу, как просили. ОБРАТИМЫЕ: claw-compactor (RewindStore, хранение оригиналов по хэшу с подстановкой маркера), clipforge-PAKT (L1-L3, decompress возвращает вход байт в байт), toon-format/toon (JSON туда и обратно), Context-fold (реестр по хэшу, разворот по требованию), tacc (лосслесс-кодек, но выход бинарный — годится как метод измерения, не как транспорт к модели). С ПОТЕРЯМИ: LLMLingua (перплексия), Opencode-DCP (активное выбывание из окна), ppgranger/token-saver (срезка шума в выводе CLI с гарантией сохранения ошибок — потери контролируемые и доказанные тестами). ИЗМЕРЕНИЕ: devwithmj/llm-token-formats-benchmark, у него же в качестве второго варианта nextmoca/context-selection-bench (Apache-2.0, но 0 звезд, поэтому в список не взят).

Лицензионные предупреждения, требующие решения владельца. Opencode-DCP — AGPL-3.0: код брать нельзя, он заражает все слинкованное, а Фемида несет ПД доверителей и открываться не может; берем механизм по п. 5 ст. 1259 ГК РФ и пишем своим. Context-fold — gh api вернул 404 на эндпоинте лицензии, значит лицензия не определена: код запрещен (п. 1 ст. 1229 ГК РФ), метод свободен. thom-heinrich/chonkify выдал NOASSERTION и по этой причине в список не включен, хотя по описанию бьет LLMLingua на извлекающем сжатии. Остальные семь — MIT или Apache-2.0, код разрешен.

Чего НЕ нашлось, говорю честно. Ни одного проекта, который целится в РУССКУЮ прозу: запросы «russian text compression», «cyrillic tokenizer efficiency», «сжатие контекста LLM», «prompt compression russian» дали либо пусто, либо студенческие BWT/LZ77-упражнения без отношения к токенам. Ни одного обратимого компрессора именно для markdown-прозы — все лосслесс-решения целятся в структурированные данные (JSON, CSV, логи, таблицы), и это само по себе ответ: обратимо жмется структура, не текст. Кэша по хэшу фрагмента как отдельного зрелого проекта тоже нет — есть только внутри claw-compactor (RewindStore) и Context-fold.

Практическая последовательность, если брать одно. Сначала стенд замера на нашем материале с токенизацией через tiktoken (девятый кандидат, час работы), чтобы ноль перестал быть ощущением. Потом ворота pakt_inspect по образцу второго кандидата: решать «жать или не жать» ДО работы. Потом дедупликация по хэшу между вызовами (четвертый кандидат) — там наибольший неснятый выигрыш. TOON и стадии claw-compactor подключать после, когда станет видно, какой класс материала сколько весит.

Ограничение метода: сеть шла только через gh, поиск GitHub несколько раз упирался в общий лимит аккаунта (403), запросы шли с отступом и повтором. Ни один репозиторий не клонирован и не запущен, на диск ничего не записано, кроме временного скрипта пагинации в скретчпаде.

Угол — локальное распознавание и разбор первички. Прогнал около двадцати формулировок на английском и русском (Cyrillic-запросы из нескольких слов gh отдает пустыми, работают только короткие). Восемь кандидатов, все живые (правки в течение месяца, кроме отдельно оговоренных), все с определенной лицензией — ни одного NOASSERTION в списке.

Главная находка: наша связка bin/vision-doc плюс markitdown закрывает середину конвейера и не закрывает КРАЯ. Слева нет подготовки скана (выравнивание, чистка, поворот, отказ по качеству) — это OCRmyPDF, auge. Справа нет структуры (порядок чтения, колонтитулы, таблицы без линеек, разорванные между страницами) — это img2table, dedoc, surya. И у самого Apple Vision мы берем один вызов из многих: partitioned OCR у mac-ocr, режим livetext через VisionKit у OCRmyPDF-AppleOCR, штрихкоды и оценка качества у auge — все это уже лежит в системе бесплатно, мы просто не звали.

Про русский, как просили. Прямое доказательство работы на русских юридических документах есть РОВНО У ОДНОГО кандидата: ispras/dedoc, ИСП РАН, грант Фонда содействия инновациям, в README разобраны русский закон и русское ТЗ. У mac-ocr, OCRmyPDF-AppleOCR и auge вопрос языка не стоит: движок там наш же, системный Apple Vision, который кириллицу уже берет. У img2table и OCRmyPDF-preprocessing вопрос языка не применим по построению — они работают с геометрией и яркостью, буквы несет наш движок; это самый безопасный класс заимствования, и я поставил их выше. У kraken и surya доказательств на русском НЕТ, и оба — обучаемые или VLM-модели, то есть тот же класс, что отклоненный 02.08.2026 MLX-порт; обоих беру с прямым запретом ставить в основной проход без пилота, kraken только в зону Буринского, surya только как геометрию блоков при тексте от Vision.

Две честные дыры. Первая — СЕГМЕНТАЦИЯ СКЛЕЕННЫХ ДОКУМЕНТОВ в одном PDF (где кончается один документ и начинается следующий). Область называется Page Stream Segmentation, публичный эталон TABME++, метрики STP и page-F1. Достойного кандидата НЕТ: agiagoulas/page-stream-segmentation — 7 звезд, MIT, модели на англоязычном Tobacco800; tieo/papercut честно пишет в README, что он пре-альфа, ни одна модель не берет планку 95 процентов STP, и лицензия у него не определена (gh api вернул NOASSERTION), то есть код брать нельзя, метод и наблюдение — можно. Названия области, эталона и метрик — само по себе полезное знание, но кода под этот пробел я не нашел. Практический обход на сегодня — штрихкод и QR через auge как детерминированная граница, там где они есть.

Вторая дыра — РУССКАЯ РУКОПИСЬ. Все, что нашлось (AmalAkh, NastyBoget/hrtr, HKR_Dataset, десяток хакатонных репозиториев), либо без лицензии, либо мертво: у hrtr при MIT последний коммит 01.05.2023, дальше трогали только метаданные. В список не включаю ни один — правило про мертвый проект держу. Реальный путь тут — kraken как движок плюс модель для кириллицы со стороны, и обязательный пилот на материале дела до любого внедрения.

Наконец, отдельно для МЕТИДЫ и ЛИНКЕЯ по моему углу ничего нет — это ожидаемо, угол про распознавание, все восемь кандидатов легли в Фемиду.
