# Общее ядро охотников за практикой

Обязательно для practice-hunter-classic / -skeptic / -tactical: читается координатором ПЕРВЫМ действием, исполняется как часть его инструкции. В файле агента — только персона, зона и специфика.

## Экономика (канон из замеров)
Каждое обращение к инструменту пересылает весь контекст заново. Материал до 15 000 токенов — субагенту ТЕКСТОМ в промпте, не путем. Механика — скриптом, не рассуждением: доверификация 4 актов моделью стоила 243 605 токенов, скриптом — около 6 000 на акт, и точнее.

## Входной контракт (по диску)
Вход — `cases/{client}/{case}/`. Нет маркера `## КАРТА ГОТОВА ✓` в `01_context/knowledge-map.md` ИЛИ раздел «7. Правовые вопросы» пуст → СТОП: «Вернуть case-mapper». Нет `knowledge/practice_index.md` → не СТОП: пометка «база знаний пуста» в шапке. Плюс проверки из файла агента. Карту целиком листьям не передавать — только выжимки.

## Шаг 0. Preflight каналов — ДО охоты
`python3 scripts/preflight_search.py` — одна команда: sgai, ключи MCP, публикаторы.
- Итог — явный список «доступно / недоступно» в шапке hunter-файла; листьям — только живые каналы.
- Код возврата 1 (внешних каналов нет) → охоту НЕ запускать: честный отчет по `knowledge/practice_index.md` с пометкой «внешний поиск недоступен».
- MCP (Firecrawl, Tavily) агенту с явным списком `tools` НЕ наследуются — в порядок поиска не включать (урок: добор через Tavily — 249 950 токенов впустую).
- Квота WebSearch программно не видна: лист, получивший «quota exceeded», фиксирует это в строке-подтверждении; канал мертв для всего роя, повторы запрещены.

## Шаг 0.5. База знаний — ДО внешнего поиска
`grep -i -B 1 -A 7 "{2-3 ключевых слова}" knowledge/practice_index.md` по каждому вопросу (команда полная). Совпадения — листьям текстом; покрытое внешне не искать. Записи «⚠ >2 лет» — на проверку актуальности.

**Гейт охоты.** По вопросу нашлись ДВЕ и более верифицированные записи (с полем «Источник» и реквизитами акта) — внешний поиск по этому вопросу НЕ запускать, работать по базе. Один охотник стоит 72-81k токенов; повторная охота по покрытой теме — чистый убыток. Внешний поиск открывается только на вопросы, где записей меньше двух либо все они старше двух лет.

**Порядок каналов по практике.** 1) `knowledge/practice_index.md` грепом — бесплатно и мгновенно. 2) `practice_search.py` — разрешён решением владельца 03.08.2026; фильтры по инстанции и региону, `--doc URL` для дословной цитаты, кеш 14 суток, квоту WebSearch не тратит. **Широкий вопрос гнать с `--partition`:** одна выдача sudact ограничена — на запросе «взыскание неустойки по договору подряда» счётчик показывает тысячи документов при двух десятках достижимых. Партиционирование по 85 регионам (при недоборе — дробление по инстанциям) поднимает выборку, но НЕ делает её полной. Скрипт печатает **охват долей**: «собрано 92 из заявленных 6 955 — охват 1,32%». Это число обязано попасть в hunter-файл строкой «охват выдачи: N% (собрано X из Y)». Писать «практика по вопросу такая», просмотрев процент выдачи, запрещено: это не вывод, а верхушка списка. Охват ниже 10% — сузить запрос статьёй, датами или судом и прогнать заново.

## Рой листьев
Узлы, модель, префикс — файл агента. Все листья ОДНИМ сообщением, параллельно, каждый `run_in_background: false`. Вход — выжимки текстом, пути не передавать. Возврат — `_working/fragments/{префикс}_{slug}.md` (slug латиницей-дефисами) + строка-подтверждение. Координатор сам не ищет. Перед запуском: `mkdir -p "cases/{client}/{case}/01_context/_working/fragments"` (путь полный).

## Каркас промпта листа (заполнить {}, добавить блок специфики агента)
```
Ты — лист-искатель охотника {имя}. {блок специфики}
Дело: {client}/{case} | Узел: {вопрос|блок} | Кодекс: {ГПК|АПК|КАС|СК}
Вопросы дела (контекст, не искать): {список} | Из базы: {выдержки} | Живые каналы: {preflight}
ПОРЯДОК:
1. Записи базы → «из базы знаний». Внешний поиск — только по непокрытому, только живые каналы:
   WebSearch/WebFetch → scripts/fetch_url.sh "URL" → sgai search "..." --json.
   «quota exceeded» → канал мертв, не повторять. Из памяти — только с пометкой «требует верификации».
2. Иерархия источников (ниже — только если выше пусто): Пленум ВС РФ → Обзоры Президиума ВС РФ →
   определения коллегий ВС РФ (2022+) → арбитражные округа → апелляция субъектов.
   Первоисточники: КС → ksrf.ru | ВС → vsrf.ru | № А... → kad.arbitr.ru | СОЮ → ГАС «Правосудие»
   (sudact.ru — агрегатор). Акт до 2020 → проверь, нет ли новее по той же норме.
3. Верификацию НЕ рассуждай: в конце фрагмента блок «К ВЕРИФИКАЦИИ» — строка на акт:
   {номер} | {дата} | {суд} | {URL}. Проверит координатор скриптом.
4. Цитаты норм, Пленума, КС — дословно либо не цитировать; купюра только с <...>; редакцию нормы
   проверить на текущую дату — утратившую силу не цитировать; иначе «пересказ, не цитата».
ЛИМИТЫ: ≤3 акта на узел; ≤300 токенов на акт; чужой узел → [кросс: N];
акт новее записи индекса → [ОБНОВИТЬ ИНДЕКС: {старое} → {новое}].
Сохрани фрагмент: {полный путь}. Верни: «Лист {slug} готов. Актов: N. Каналы: {статус}».
```

## Верификация актов — скриптом, обязательный порядок
1. Номера из блоков «К ВЕРИФИКАЦИИ» всех фрагментов — одним вызовом `python3 scripts/verify_act.py {номер1} {номер2} ...` (известен URL → `--url`). Читать только итоговую таблицу.
2. ПОДТВЕРЖДЕН → «Первоисточник: подтверждено ({сайт}, ДД.ММ.ГГГГ)». РАСХОЖДЕНИЕ → сверить, какая дата — акта, какая — публикации (боевой случай: 13.06.2019 у № 81-КГ19-2 — дата публикации); не разрешилось → «требует проверки». НЕ НАЙДЕН → «требует проверки».
3. ПРЕДМЕТ акта обязан совпадать с позицией — акт «о другом» = подмена, не включать (боевой случай: КС № 1-П от 14.01.2016 — пенсионное дело, выдавали за иное).
4. Ссылка из чужого документа дела → верифицировать ДО заимствования; подмена → раздел «Подмены в чужих документах».
5. Публикатор недоступен → «требует проверки»; подтверждение не выдумывать.

## Синтез — общие правила
- Читать только свои фрагменты и итог verify_act; новых поисков не делать.
- Дубль акта → одна запись; [кросс: N] → в раздел своего узла.
- **Неподтвержденное — только в раздел «НЕ ЦИТИРОВАТЬ до проверки»**, с подтвержденным не смешивать (урок 28.07.2026: пять невалидных определений пролежали два месяца). Позиция только на неподтвержденном → «не подтверждена первоисточником».
- Реквизиты не выдумывать; нет номера → «номер не найден — требует верификации».
- Контракт Фемиды (сверяется дословно): не менее трех источников с точными реквизитами формата `Постановление Пленума ВС РФ от ДД.ММ.ГГГГ № X` и `Определение СКГД ВС РФ от ДД.ММ.ГГГГ № X-КГXX-XX`; резюме по каждому источнику; процессуальный угол (каким документом, на какой стадии); формула «суд рассмотрел» запрещена.

## Сбои
- Лист упал / фрагмента нет → перезапуск (максимум 2); снова → узел в «Не найдено»: «лист упал дважды».
- Все внешние каналы мертвы → правило preflight; молча не деградировать.
- Публикатор недоступен → «требует проверки» → «НЕ ЦИТИРОВАТЬ до проверки».
- <3 подтвержденных после синтеза → один дополнительный круг; снова <3 → в рапорте «контракт не выполнен: {N} источников», полноту не имитировать.

## Самопроверка — по диску, не по памяти
Перечитать hunter-файл С ДИСКА: 1) ≥3 источника с реквизитами, у каждого резюме и процессуальный угол; 2) неподтвержденное — только в «НЕ ЦИТИРОВАТЬ до проверки»; 3) `grep -n "суд рассмотрел" {файл}` и `grep -n "ё" {файл}` — пусто, даты только ДД.ММ.ГГГГ; 4) «Источники» покрывает каждый акт, обязательные разделы на месте. Провал → исправить, перечитать заново, лишь затем рапорт.

## Инвариант завершения — НАРУШЕНИЕ = ПРОГОН ОПЛАЧЕН ДВАЖДЫ
**ЗАПРЕЩЕНО возвращать управление до того, как файл `hunter_*.md` записан на диск. Отчет о запуске листьев результатом не является.**
Урок 28.07.2026 (четыре нарушения на двух делах): листья спавнили фоном, ход завершался сам — повторное пробуждение стоило около 175 000 токенов. Механика: каждый субагент `run_in_background: false`; параллелизм — несколько синхронных вызовов одним сообщением. Лист не вернулся после двух запусков → «данных по узлу нет», синтез завершить без него: файл с пробелами полезнее пустого места.
