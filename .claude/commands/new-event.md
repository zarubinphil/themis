# /new-event — событие по делу

## Вход и валидация

`$ARGUMENTS` = `{клиент} {дело} {ДД-ММ-ГГГГ} {название}` (название — латиница-дефисы: `osnovnoe-zasedanie`, `apellyaciya`).

| Ситуация | Действие |
|---|---|
| Все 4 аргумента | Проверить: `cases/{клиент}/{дело}/` существует, дата корректна → алгоритм |
| Дело не указано | Взять из контекста сессии, объявить; нет → СПРОСИТЬ |
| Даты нет | СПРОСИТЬ — не ставить сегодняшнюю молча |
| Дата в другом формате (2026-06-10, 10.06.2026) | Привести к `ДД-ММ-ГГГГ` для имени папки, объявить |
| Папка события уже существует | СТОП, показать путь — не пересоздавать и не затирать |

## Алгоритм

1. Создать `cases/{клиент}/{дело}/02_hearings/{ДД-ММ-ГГГГ}_{название}/`.
2. `_event.md` по шаблону `cases/_templates/_event.md`. Суд / Номер дела / Судья — из `_case.md`; нет данных → `—`, не выдумывать.
3. Обновить `_case.md`:
   - «Следующее заседание» → дата события `ДД.ММ.ГГГГ` (если событие будущее).
   - «Журнал событий» → строка `| ДД.ММ.ГГГГ | {тип события} | — |`.
4. Итог:

```text
✓ Событие: 02_hearings/{ДД-ММ-ГГГГ}_{название}/
  Заполни _event.md: задача, ожидаемая позиция оппонента
  Документы к событию — /draft (doc-drafter), подготовка — hearing-prep
```

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Дела нет в `cases/` | СТОП, показать похожие строки из `_index.md`, предложить /new-case |
| `_case.md` отсутствует | Событие создать, отсутствие `_case.md` отметить в итоге |
| Шаблон `_event.md` отсутствует | Создать файл с разделами «ДО СОБЫТИЯ» / «ПОСЛЕ СОБЫТИЯ», отметить отсутствие шаблона |

## Самопроверка перед возвратом (по диску)

- [ ] Папка события и `_event.md` существуют (`ls`)
- [ ] `_case.md` перечитан: дата и журнал обновлены
- [ ] Даты в текстах `ДД.ММ.ГГГГ`, в имени папки `ДД-ММ-ГГГГ`, нет буквы «ё»
