# /new-case — новое дело

## Вход и валидация

`$ARGUMENTS` = `{клиент} {дело-год}` (латиница-дефисы, дело с годом: `razvod-2026`).

| Ситуация | Действие |
|---|---|
| Оба аргумента есть | Проверить формат → шаг 0 |
| Аргументов нет, клиент ясен из контекста | Предложить `{клиент} {дело-год}`, дождаться подтверждения |
| Клиент не определяется | СПРОСИТЬ «чье дело и предмет?» — не выдумывать имя папки |
| Кириллица/пробелы в аргументах | Транслитерировать в латиницу-дефисы, показать до создания |

## Алгоритм

### 0. Маршрутизация — читать `cases/_clients.md` ПЕРВЫМ

| В реестре | Действие |
|---|---|
| Клиент найден (ФИО / псевдоним / ИНН) | Использовать ЕГО канонический folder, новый не создавать |
| Компания, владелец известен (✓) | Папка ВЛАДЕЛЬЦА: компания = сущность, клиент = владелец |
| Компания, владелец неизвестен (⚠) | Предупредить, временно папка компании |
| Два похожих кандидата | СПРОСИТЬ, не выбирать самому |
| Не найден | Новая папка + строка в `_clients.md` (шаг 4) |

Клиент существует → прочитать `cases/{клиент}/_client.md` (данные подтянуть в `_case.md`) и `cases/_relationships.md` (связи с оппонентом). Сообщить: «Клиент найден. Активных дел: N».

### 1. Структура папок

```bash
mkdir -p cases/{клиент}/{дело}/{00_intake,01_context/_working,01_context/_practice,01_context/_council,02_hearings,03_drafts,04_archive}
```

Папка дела уже существует → СТОП, спросить: дубль или продолжение. `knowledge-map.md` / `practice.md` / `positions.md` здесь НЕ создавать — только workflow-агенты после консенсуса.

### 2. Инбокс `~/Desktop/inbox/` — переносить ТОЛЬКО группу нового дела

Инбокс бывает мультидельным (~100 файлов разных дел — прецедент 19.07.2026). Перемещать все подряд ЗАПРЕЩЕНО.

1. Инвентарь: только файлы верхнего уровня; `unsorted/` и `_processed/` не трогать. Пусто → пропустить шаг, сообщить.
2. Группировка по времени: `stat -f '%m %N' ~/Desktop/inbox/*` → самый свежий mtime, группа = файлы в окне 3600 сек от него.
3. Тематическая сверка КАЖДОГО файла группы ДО mv: `python3 scripts/markdown_extract.py "FILE" --json-meta` → первая страница из кеша → совпадает ли с делом (ФИО клиента/оппонента, предмет). `.md` — читать напрямую.
4. Решение по таблице:

| Файл | Действие |
|---|---|
| В окне + тема совпадает | Переносить |
| В окне, тема чужая или неясная | НЕ переносить, включить в вопрос пользователю |
| Вне окна | Не трогать, записать в `cases/_index.md` → раздел «Inbox» |
| OCR/извлечение пустое | Не «нет текста»: точечный vision-фолбэк одной страницы или спросить |
| Любое сомнение | СПРОСИТЬ списком, не перемещать |

5. В группе директория → до mv проверить вложенные дубли: `find DIR -type d`; кандидатов сверить `diff -rq A B`; идентичны → перенести один, различаются → спросить.
6. `mv` только утвержденную группу → `00_intake/`. Список перемещенного и оставленного — в итог.

### 3. `_case.md`

По шаблону `cases/_templates/_case.md`. ФИО, ИНН, связи — из `_client.md`. Дата открытия — сегодня, `ДД.ММ.ГГГГ`. Неизвестное — `—`, не выдумывать.

### 4. Три реестра — все три, не выборочно

- `cases/_index.md` → строка `| {Клиент} | {Предмет} | {папка}/{дело} | ИНН | ИНН опп. | № дела | Суд | Активно |`.
- `cases/{клиент}/_client.md` → «Активные Дела» + строка. Новый клиент → создать `_client.md` из `cases/_templates/_client_template.md`.
- `cases/_clients.md` → новый клиент → строка в «Физические лица» или «Компании».

### 5. Итог

```
✓ Дело создано: cases/{клиент}/{дело}/
  Перемещено из инбокса: N файлов (список) · Оставлено в инбоксе: M
  Следующий шаг: case-mapper → knowledge-map.md
```

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| `cases/_clients.md` отсутствует | СТОП: реестр маршрутизации обязателен, сообщить пользователю |
| Папка дела уже существует | СТОП, спросить: дубль или продолжение |
| `markdown_extract.py` упал на файле | Файл не переносить, пометить «требует проверки», продолжить с остальными |
| Инбокс пуст или недоступен | Шаг 2 пропустить, остальное выполнить |
| Клиент неоднозначен | СПРОСИТЬ, папку не создавать |
