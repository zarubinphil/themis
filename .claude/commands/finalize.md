# /finalize — финальный PDF с подписью

## Вход и валидация

| Ситуация | Действие |
|---|---|
| Путь к `.docx` указан | Проверить, что файл существует |
| Указано `{клиент}/{дело}` | Взять самый свежий `.docx` из `03_drafts/` либо `02_hearings/{последнее событие}/`, объявить какой |
| Ничего не указано | Дело из контекста сессии; нет → СПРОСИТЬ |
| Вердикта `ГОТОВ К ПОДАЧЕ` от Кони нет | Предупредить, продолжать только по явному подтверждению пользователя |

## Guard правок доверителя — ДО любых операций с .docx (обязательно)

Уже выданный `.docx` доверитель мог править напрямую в Word (прецедент 14.07.2026 — правки молча затерты пересборкой).

1. Есть снимок `03_drafts/_baselines/{имя}.docx` → извлечь оба через `python3 scripts/markdown_extract.py FILE --json-meta`, сравнить тексты.
2. Направление правки: `officecli get FILE /` → `lastModifiedBy` / `revisionNumber` (фолбэк: `unzip -p FILE docProps/core.xml`). `revision` > 1 и чужой `lastModifiedBy` = правил доверитель. Режим рецензирования → `officecli get FILE /revision` (точный список правок с авторами).
3. Отличия есть → это правки доверителя → **СТОП**: не пересобирать, не перезаписывать. Предложить redline-разбор («изучи мои правки») или спросить, как поступить.
4. Отличий нет → продолжать.

## Алгоритм

1. Подпись: проверить `cases/_assets/подпись.png`. Нет → `⚠ Подпись не найдена: cases/_assets/подпись.png. Добавь PNG → повтори /finalize` (либо `--no-sign`).
2. `python3 scripts/sign_and_pdf.py "{путь_к_docx}"` (варианты: `--no-sign` — только PDF, `--sign-only` — только подпись на готовый PDF). Конвертация через Microsoft Word, подпись — на блок подписи последней страницы.
3. Пакет в папку события: `.md` + `.docx` + `.pdf` → `02_hearings/{ДД-ММ-ГГГГ}_{событие}/`. Папки события нет → создать через /new-event (дату СПРОСИТЬ), в корень `02_hearings/` не класть.
4. `_event.md` → отметить документ подписанным/поданным, дата `ДД.ММ.ГГГГ`.
5. С этого момента документ ПОДАН — не редактировать (железное правило). Правки только новым документом.

Структура папки события после финализации:

```text
02_hearings/ДД-ММ-ГГГГ_название/
  _event.md
  {документ}.md       ← источник (Markdown)
  {документ}.docx     ← финальный Word
  {документ}.pdf      ← финальный PDF с подписью (для подачи)
```

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Baseline отличается от текущего `.docx` | СТОП: правки доверителя — redline-разбор или вопрос, не перезаписывать |
| Снимка в `_baselines/` нет | Предупредить (сравнить не с чем), продолжать по подтверждению |
| Word/конвертация упала | Повторить 1 раз; снова сбой → СТОП, сообщить (PDF вручную) |
| Подписи нет | Сообщить, предложить `--no-sign` |

## Самопроверка перед возвратом (по диску)

- [ ] Guard `_baselines/` выполнен ДО конвертации
- [ ] `.pdf` существует рядом с `.docx` в папке события (`ls`)
- [ ] `_event.md` перечитан — отметка о подаче стоит
- [ ] Поданные файлы после финализации не редактировались
