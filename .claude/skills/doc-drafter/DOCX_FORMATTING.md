# Форматирование .docx — обязательный стандарт практики

> **Статус: обязательный. Отступление запрещено.** Утвержден владельцем 03.08.2026.
> Ни один параметр этого файла не является рекомендацией. Документ, собранный иначе,
> в суд не выпускается и переделывается целиком.
> Единственный способ изменить стандарт — новое прямое решение владельца с правкой
> этого файла, `scripts/create_docx.py` и `scripts/document_guard.py` в один заход.
>
> Параметры параграфов ЗАШИТЫ в `DocBuilder` (`scripts/create_docx.py`) — вручную не задавать.
> Проверяет соблюдение не человек, а `scripts/document_guard.py`. Его вердикт окончателен.

## §1 Шрифт — одна гарнитура на весь документ

| Роль | Гарнитура | Где применяется |
|---|---|---|
| Всё | **PT Serif** | титул, шапка, разделы, тело, таблицы, `ПРОШУ:`, `ПРИЛОЖЕНИЯ:`, подпись, номер страницы |

Решение владельца 04.08.2026. Отменяет набор из четырех гарнитур (Playfair Display +
PT Serif + Golos Text + PT Mono) от 03.08.2026. Второй гарнитуры в документе нет —
`document_guard.py` считает любую другую чужим шрифтом и заваливает проверку.

**Иерархию держат кегль, начертание и разрядка, а не смена шрифта.** Кегли 14/13/12/11
(§4), полужирный на заголовках и метках сторон, разрядка титульного блока: заголовок
3 pt, подзаголовок 0,6 pt (`TRACK_TITLE_PT` и `TRACK_SUBTITLE_PT` в `create_docx.py`,
ставит `add_title` / `add_subtitle` сами).
**QuickLook на macOS разрядку не отрисовывает** — предпросмотр ее «отсутствия» ничего
не доказывает, проверять в Word либо по XML (`grep 'w:spacing w:val="60"'`).

PT Serif — SIL Open Font License, кириллица полная.
Установка на новую машину (без нее документ соберется, но на экране покажет подмену):

```bash
b=https://raw.githubusercontent.com/google/fonts/main/ofl
curl -sL -o ~/Library/Fonts/PT_Serif-Web-Regular.ttf    $b/ptserif/PT_Serif-Web-Regular.ttf
curl -sL -o ~/Library/Fonts/PT_Serif-Web-Bold.ttf       $b/ptserif/PT_Serif-Web-Bold.ttf
curl -sL -o ~/Library/Fonts/PT_Serif-Web-Italic.ttf     $b/ptserif/PT_Serif-Web-Italic.ttf
curl -sL -o ~/Library/Fonts/PT_Serif-Web-BoldItalic.ttf $b/ptserif/PT_Serif-Web-BoldItalic.ttf
```

Golos Text, PT Mono и Playfair Display больше не нужны; `scripts/make_playfair.py`
(нарезка статических начертаний Playfair) с этим решением осталась без работы.

**Почему не Times New Roman.** ГОСТ Р 7.0.97-2016 п. 3.3 дословно: «Для создания документа
на компьютере необходимо использовать свободно распространяемые бесплатные шрифты».
Times New Roman — проприетарная гарнитура Monotype. Плюс у PT Serif выше высота строчных,
строка читается быстрее. Times New Roman в наших документах не используется вовсе;
`document_guard.py` считает его чужим шрифтом и заваливает проверку.

**Подмены шрифта у адресата не происходит:** подаем PDF либо бумагу, гарнитуры внедряются
в файл. Риск возник бы только при пересылке исходного `.docx` контрагенту — так не делаем.

## §2 Нумерация страниц — безусловно, в каждом документе

Номер ставится **всегда**, независимо от объема: арабские цифры, **центр нижнего поля**,
первая страница без номера. Решение владельца 04.08.2026 — номер переехал из верхнего
поля вниз. Штамп суда о приеме ставят в правом нижнем углу, центр нижнего поля его не
занимает. Место номера проверяет `document_guard.py`: поле `PAGE` в верхнем колонтитуле
теперь считается нарушением, а не альтернативой.

`DocBuilder.save()` ставит поле сам, если составитель не вызвал `add_page_numbers()`.
Отключить нумерацию нельзя — параметра для этого не предусмотрено.
Отсутствие поля `PAGE` означает, что документ собран мимо `DocBuilder`: такой документ
бракуется без разбора содержания.

## §3 Полоса набора

Страница А4. Поля в миллиметрах:

| Профиль | верх | низ | лево | право |
|---|---|---|---|---|
| Судебный документ (по умолчанию) | 20 | **30** (зона штампа экспедиции, Приказ СД РФ № 36) | 30 | 15 |
| L3 и кассация ВС | 20 | 30 | **35** | 15 |
| Договор и прочее несудебное | 20 | 20 | 25 | 20 |

Левое поле 35 мм в коде НЕ зашито — выставлять явно: `b.doc.sections[0].left_margin = Mm(35)`.

Межстрочный интервал 1.15. Абзацный отступ тела 1.25 см. Язык ru-RU.
Кегли — ровно четыре, набор не расширяется: **14** заголовок документа · **13** подзаголовок
и дата шапки · **12** весь остальной текст · **11** блок-цитата и широкие числовые таблицы.

Выравнивание: шапка — плавающая таблица справа (колонки 38/62 процента полосы набора);
метки (`ИСТЕЦ:`) — вправо, полужирные; тело — по ширине; подпись — вправо.
Допустимые отступы первой строки: 1.25 см (тело), 0 при положительном левом отступе
(блок-цитата), отрицательный, ровно погашенный левым (висячий отступ нумерованного абзаца).

**Запрещено во всех документах:** курсив · подчеркивание · цветной текст · цветная заливка
(допустимы только серые тона: документ печатают черно-белым) · любая гарнитура вне §1 ·
любой кегль вне четырех перечисленных · рамка абзаца через `w:pBdr` (рендерится
по-разному — рамку дает только таблица 1×1).

Тело не полужирное. Полужирным — нормы, суммы, даты, термины, вывод блока: 3-5 слов
на страницу (мера — `CONTENT_DESIGN.md` §2). Внутри цитат полужирного нет.

## §4 Выбор метода DocBuilder

| Ситуация | Метод |
|---|---|
| Шапка: суд + стороны + дело | `add_header_table` |
| Досудебный документ (КОМУ/ОТ) | `add_addressee_table` |
| Заголовок / подзаголовок / дата шапки | `add_title` / `add_subtitle` / `add_header_date` |
| Разделы, подразделы | `add_section` / `add_subsection` |
| Абзац тела; полужирные фрагменты — список кортежей `(text, bold)` | `add_body`; после маркированного списка — `add_body_spaced` |
| Перечисление | `add_bullet` |
| Расчет (баланс, конвертация, сопоставление позиций) | `add_table(headers, rows, widths, font_size, aligns, borders)` — шапка полужирная, границы 0.5 pt. **Расчет списком вместо таблицы запрещен** |
| Дословная норма или цитата 40+ слов | `add_quote` |
| Просительная часть | `add_proshyu` + `add_request_item` (номер «1. » вручную) |
| Приложения | `add_appendices` + `add_appendix_item` |
| Подпись | `add_signature_table(role, name, date)` — ГОСТ, устойчиво к LibreOffice и Google Docs; `add_signature` — legacy |
| Абзац тела со сквозным номером | `add_numbered_body` — точная ссылка «пункт 14» вместо «страница 6» |
| Разделители; сохранение | `add_empty`, последним — `add_final_empty`; `save(path)` — авто: стрип «ё», нумерация страниц, baseline, guard правок |

### Нумерация пунктов — только автоматическая

Номера пунктов ведет **Word**, а не составитель. `add_request_item`,
`add_appendix_item` и `add_numbered_body` ставят настоящую нумерацию (`w:numPr`
со своим определением в `numbering.xml`), поэтому удаление, вставка и
перестановка пункта пересчитывают остальные сами. Доверитель правит документ у
себя — нумерация едет за правкой, вручную ее больше никто не переписывает.

- **Номер в тексте не набирать.** Вызов вида `add_request_item("1. Взыскать...")`
  остается рабочим — ведущий номер снимается автоматически, иначе вышло бы
  «1. 1. Взыскать». Новые вызовы писать без номера.
- **Каждый список независим:** просительная часть, приложения и сквозные абзацы
  имеют свои определения и не делят счетчик. Все три начинаются с единицы.
- **Отступы задает определение нумерации**, в параграфе их не трогать.
- **Идентификаторы нумерации продолжают шаблонные (10, 11, 12...).** Уводить их
  в отдельный диапазон нельзя: при `numId` вида 901 номера не отрисовываются
  вовсе, хотя XML схемно верен (замер 03.08.2026). Определение не собирать с
  нуля — `_new_num_def` клонирует шаблонное: собранное вручную не имеет `w:nsid`
  и `w:tmpl`, и просмотрщик его игнорирует.
- **Следствие для чтения:** номеров больше нет в тексте абзаца, они живут в
  разметке. Разбирать список приложений построчным парсингом текста нельзя —
  `document_guard.docx_appendices` берет их из нумерации.
- Римские номера разделов (`I.`, `II.`) остаются текстом: их немного, порядок
  задан структурой документа, и они входят в оглавление как есть.

## §5 Микротипография

| Элемент | Правильно | Ошибка |
|---|---|---|
| Дефис `-` | внутри слова: «во-первых», без пробелов | вместо тире |
| Тире `—` (U+2014) | пунктуация, пробелы с обеих сторон: «Ответчик — ООО» | дефис |
| Среднее тире `–` (U+2013) | диапазоны, без пробелов: «30–90 дней» | «30-90» |
| Кавычки | «елочки»; вложенные — „лапки“: «ООО „Ромашка“» | прямые `"..."` |
| Многоточие | `…` (U+2026); купюра в цитате — `[...]` | `...` |

Неразрывный пробел (U+00A0) обязателен: `И. И. Иванов` · `г. Москва` · `№ 12` · `2024 г.` ·
`500 000 рублей` (и между разрядами чисел) · `т. е.` · `§ 156`.
Числа: разряды пробелом (`1 298 300`), десятичный разделитель — запятая.
Даты: в тексте `15 марта 2024 года`, в реквизитах `15.03.2024`. Формат единый по документу.
Буквы «ё» в документах нет — `save()` заменяет ее автоматически.

## §6 Приемка — только машиной

Глазами формат не принимается. Перед выдачей документа обязательно:

```bash
python3 scripts/document_guard.py ДОКУМЕНТ.docx [--md ДОКУМЕНТ.md] [--l3 | --dogovor]
```

Код возврата 0 — документ принят. Код 1 — документ не готов, править по списку и гнать заново.
Проверяются: поля профиля, три гарнитуры, четыре кегля, интервал, отступы, выравнивание тела,
отсутствие курсива и подчеркивания, **наличие поля номера страницы**, «ё», формат дат,
сквозная нумерация приложений и упоминание каждого доказательственного приложения в тексте
(процессуальные — пошлина, ЕГРЮЛ, направление копии, доверенность — упоминания не требуют).
Собственную исправность сторож подтверждает сам: `python3 scripts/document_guard.py --selftest`.

Кони (`doc-reviewer`) проверяет содержание, а не арифметику полей: блок 6 его чек-листа —
это чтение вывода `document_guard.py`, а не самостоятельный обмер документа.
