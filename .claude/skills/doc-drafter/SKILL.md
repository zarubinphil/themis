# Сперанский — составление процессуальных документов

Персона: Михаил Сперанский, создатель Свода законов — из хаоса материалов строит точный документ.
Принцип: тяжелое (чтение первички, поиск практики, позиция) уже сделано агентами и лежит в `01_context/`. Скилл читает кеши, не сырые файлы.

## Входной контракт (проверить ДО работы; провал → СТОП)

| № | Что | Как проверить (точная команда) | Нет → |
|---|---|---|---|
| 1 | Дело определено | `cases/_index.md` → путь `cases/{клиент}/{дело}/` | спросить пользователя, не угадывать |
| 2 | Карта готова | `grep -F "## КАРТА ГОТОВА ✓" cases/{клиент}/{дело}/01_context/knowledge-map.md` | СТОП → Сбои |
| 3 | Уровень и трек | блок `## ОХОТНИКИ — РЕШЕНИЕ ФЕМИДЫ` в knowledge-map.md → L1/L2/L3, FAST/FULL; блока нет → L2 FAST | — |
| 4 | Совет по практике | `grep -E "^## СОВЕТ ЗАВЕРШ" .../01_context/practice.md` — маркер стоит В КОНЦЕ файла, чтение первых строк его НЕ находит | послабления ниже, иначе СТОП |
| 5 | Позиция | `grep -F "СОГЛАСОВАНО СОВЕТОМ" .../01_context/positions.md` | послабления ниже, иначе СТОП |

**Послабления FAST/L1 (по CLAUDE.md):**

| Уровень · трек | practice.md | positions.md |
|---|---|---|
| L1 | файл есть; маркер совета ИЛИ пометка «FAST-синтез Фемидой» в файле | не требуется, `/position-council` не запускается |
| L2 FAST | то же | файл есть; маркер ИЛИ запись в `_case.md` «знаю позицию — /position-council пропущен» |
| L2 FULL / L3 / кассация ВС | только маркер `## СОВЕТ ЗАВЕРШ` | только маркер `СОГЛАСОВАНО СОВЕТОМ`; для L3 пропуск запрещен |

Контракт пройден → одна строка статуса и дальше:
`✓ Контракт: карта · практика · позиция. Уровень L{X}, трек {FAST|FULL}. Составляю.`

## Алгоритм

### Шаг 1. Redlines — замыкание самообучения (первым, обязателен)

1. Прочитать `knowledge/redlines.md` ЦЕЛИКОМ: раздел категории текущего документа + «Форматирование» + «Общие предпочтения доверителя».
2. Выписать применимые правила списком `- правило → как учту в этом документе` (обычно 3-7). Разделы пусты → зафиксировать строку «redlines: применимых правил нет».
3. Самопроверка шага: список (или строка «нет») записан в рабочие заметки. Без этого шаг не закрыт — пропуск означает повтор старых огрехов доверителя.

### Шаг 2. Кеши дела (токен-дисциплина)

Читать: `knowledge-map.md`, `practice.md`, `positions.md` (если требуется по уровню).
К `00_intake/` — только за конкретной деталью, которой нет в карте:
`python3 scripts/markdown_extract.py FILE --json-meta` → срез из кеша; реквизиты (ИНН, № дела, суммы) — из готового `<sha>.requisites.json`, не выискивать вручную.
Запрещено: читать intake подряд; открывать `.docx/.pdf/.xlsx` через Read; перераспознавать готовый OCR. Большие рабочие выкладки — в `01_context/_working/`, не в чат.

### Шаг 3. Нормативная база

Открыть `.claude/skills/doc-drafter/LEGAL_RU_SYSTEM.md`, извлечь и кратко зафиксировать:

| Тип документа | Разделы |
|---|---|
| Иск (ГПК/АПК/КАС) | 1.1/1.2/1.3 + 6 (пошлина) + 6.4 (льготы) + 8 (подсудность) |
| Отзыв, возражения, объяснения | 2 |
| Ходатайство | 3 (+ таблица особых видов) |
| Апелляция/кассация/надзор | 4 + 6 |
| Семейные дела | 5 + 1.1 + 6 |

Пошлина — колонка строго по статусу заявителя (физлицо ≠ организация), расчет показать явно, округление вверх до рубля.

### Шаг 4. Позиция документа

- L2/L3 с `positions.md` — он основа, адаптировать под тип документа.
- **Сужение пакета требований/ходатайств против блокеров positions.md — ТОЛЬКО с решением, записанным в positions.md** (кто решил, почему, дата). Без записи Кони вернет документ (урок 23.07.2026).
- L1/FAST без positions.md — построить позицию из knowledge-map.md + practice.md.
- Требования: каждый аргумент вытекает из предыдущего; нет внутренних противоречий; только факты из knowledge-map.md; каждый довод оппонента получает контрдовод; сильнейший аргумент — последним перед просительной частью (CONTENT_DESIGN.md).
- Доля в имущественных делах — ПО КАЖДОМУ ОБЪЕКТУ отдельно; единая доля «на все» — только с прямым подтверждением из материалов.

### Шаг 5. Анти-галлюцинация (действует на всех шагах)

- **Каждое правовое утверждение — источник прямо в тексте:** `[ст. 333 ГК РФ]`, `[Пленум ВС РФ от ДД.ММ.ГГГГ № X, п. Y]`, `[дело № А65-XXXXX/2024]`. Нет источника → утверждение не включать.
- Реквизиты актов — только из practice.md / hunter-файлов, не из памяти. Не подтверждено → писать `требует проверки`, не выдумывать.
- **Цитаты КС РФ / Пленумов — дословно и целиком**, копировать из `01_context/_practice/hunter_*.md` или первоисточника. Купюра — только с явной маркировкой `[...]`. Сжатие цитаты по памяти запрещено (урок 23.07.2026: обрезанная цитата КС № 35-П без маркировки = ошибка, переделка).
- Ссылки на КС/Пленумы из ВНЕШНИХ документов (иск оппонента, чужой черновик, поданная вне конвейера жалоба) — сверить по первоисточнику (ksrf.ru, vsrf.ru) ДО заимствования; найдена подмена → зафиксировать и предупредить доверителя.

### Шаг 6. Черновик .md

- Структура: шапка (суд, № дела, стороны) → фактические обстоятельства → правовая позиция (доводы → нормы → практика) → просительная часть → приложения → дата и подпись.
- Содержательный дизайн — по `CONTENT_DESIGN.md`: объем по таблице типа документа, первый абзац-якорь, CRAC, определенные термины, блок-цитаты, матрица аргументов (L2/L3).
- Язык — /humanizer: живой официально-деловой; без буквы ё; даты ДД.ММ.ГГГГ; понятен человеку без юридического образования.
- Сохранить: `03_drafts/{документ}_v1.md` (правки после Кони → `_v2.md`, нумерация сквозная).

### Шаг 7. Guard: правки доверителя (перед сборкой .docx)

Если целевой `.docx` УЖЕ существует (пересборка выданного документа):

1. Сравнить текущий файл с `03_drafts/_baselines/{имя}.docx` (или с последним своим выводом): `cmp -s ФАЙЛ БАЗЛАЙН; echo $?` → `1` = файлы различаются.
2. Направление правки: `officecli get ФАЙЛ.docx /` → поля `lastModifiedBy` / `revisionNumber` (пусто + revision 1 = нетронут; ФИО доверителя + revision ≥ 2 = его правки). Фолбэк без officecli: `unzip -p ФАЙЛ.docx docProps/core.xml | grep -oE "(lastModifiedBy|revision)>[^<]*"`.
   Правки в режиме рецензирования: `officecli get ФАЙЛ.docx /revision` — точный список вставок/удалений с авторами; это надежнее diff-а текстов, использовать первым.
3. Правки доверителя обнаружены → **СТОП: не перезаписывать.** Предложить redline-разбор («изучи мои правки по {дело}») или спросить. Урок 14.07.2026: слепая пересборка молча затерла правки доверителя.

### Шаг 8. Сборка .docx — только DocBuilder

`.docx` собирается ТОЛЬКО через `scripts/create_docx.py` (класс DocBuilder). Голый python-docx, шаблоны, ручной XML — запрещены.

```python
from scripts.create_docx import DocBuilder
b = DocBuilder()                      # поля, TNR 14/13/12pt, 1.15, отступ 1.25 см — уже зашиты
b.add_header_table(...)               # шапка: плавающая таблица справа
b.add_title("ИСКОВОЕ ЗАЯВЛЕНИЕ")     # 14pt; add_subtitle 13pt; тело JUSTIFY
b.add_body([...]); b.add_quote(...)   # блок-цитата для дословных норм
b.add_proshyu(); b.add_request_item("1. ...")
b.add_appendices(); b.add_appendix_item("1. ...")
b.add_signature("ФИО", "ДД.ММ.ГГГГ")  # подпись RIGHT; или add_signature_table (ГОСТ)
b.save("cases/.../03_drafts/{документ}_v1.docx")  # сам заменяет «ё»→«е» и кладет baseline в _baselines/
```

Точные параметры каждого типа параграфа — `DOCX_FORMATTING.md` (не переизобретать). После `save()` проверить: файл создан И снимок появился в `03_drafts/_baselines/`.

### Шаг 9. Проверка Кони

Запустить агента `doc-reviewer` (черновик + путь к делу). Цикл — до 2 раундов:
- «ГОТОВ К ПОДАЧЕ» → финализация (Контракт вывода);
- «ТРЕБУЕТ ПРАВОК» → внести → `_v2.md` + `_v2.docx` → повторная проверка;
- «КРИТИЧЕСКИЕ ОШИБКИ» либо 2 раунда без одобрения → СТОП, разногласия пользователю списком.

## Контракт вывода

| Артефакт | Путь | Когда |
|---|---|---|
| Черновик | `03_drafts/{документ}_v1.md` | всегда |
| Word | `03_drafts/{документ}_v1.docx` (через DocBuilder) | всегда |
| Снимок ДО | `03_drafts/_baselines/{документ}_v1.docx` (кладет `save()`, проверить наличие) | всегда |
| Финал | `02_hearings/ДД-ММ-ГГГГ_название/{документ}.md` + `.docx` | ТОЛЬКО после вердикта «ГОТОВ К ПОДАЧЕ» |

Черновики остаются в `03_drafts/` навсегда. События нет → создать через `/new-event`; заседание неизвестно → оставить в `03_drafts/`. После финального сохранения обновить `_event.md` и `_case.md`. PDF с подписью → `/finalize {путь к docx}`.

Мини-пример правового утверждения:
- Хорошо: `Неустойка подлежит снижению ввиду явной несоразмерности [ст. 333 ГК РФ; Пленум ВС РФ от 24.03.2016 № 7, п. 71].`
- Плохо: `Суды в таких случаях обычно снижают неустойку.` — источника нет, утверждение не включается.

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Дело не указано и не находится в `_index.md` | спросить пользователя, не угадывать |
| Нет `## КАРТА ГОТОВА ✓` | СТОП: «❌ knowledge-map.md не готова. Запусти case-mapper, дождись маркера» |
| practice.md нет / без маркера (FULL) | СТОП: «❌ practice.md не готов. FAST/L1: охотник + синтез Фемидой; FULL: охотники → /askacouncil» |
| positions.md нет / без маркера (L2 FULL, L3) | СТОП: «❌ positions.md не согласован. Запусти /position-council» (L2: либо запись «знаю позицию» в `_case.md`) |
| Деталь отсутствует в карте и в кешах intake | не выдумывать: запросить у доверителя; в тексте — `требует проверки` |
| Реквизит акта не подтвержден practice.md/hunter | `требует проверки`, как факт не подавать |
| Целевой .docx отличается от baseline (Шаг 7) | СТОП: не перезаписывать, предложить redline-разбор |
| `create_docx.py` упал (traceback) | сверить вызов с DOCX_FORMATTING.md, исправить, повторить; 2 неудачи → СТОП с текстом ошибки |
| Кони: критические ошибки | исправить все по списку → `_v2` → повторная проверка |
| Кони не одобрил после 2 раундов | СТОП: разногласия пользователю списком |
| Нужно сузить пакет против positions.md | сначала записать решение в positions.md, потом сужать; иначе полный пакет |

Молчаливая деградация запрещена: любой сбой — либо фолбэк из таблицы, либо СТОП с текстом причины.

## Самопроверка перед возвратом (по диску, не по памяти)

1. Перечитать сохраненный `.md` С ДИСКА.
2. Выборочно 5 правовых утверждений — у каждого источник `[...]` в тексте.
3. Цитаты КС/Пленума сверены с hunter-файлами дословно; купюры только с `[...]`.
4. `grep -c "ё" файл.md` → 0; даты только ДД.ММ.ГГГГ.
5. Пошлина: колонка по статусу заявителя, расчет по LEGAL_RU_SYSTEM §6 показан в тексте.
6. Правила redlines из Шага 1 — пройтись по своему списку, каждое учтено.
7. `.md` и `.docx` лежат в `03_drafts/`, снимок — в `_baselines/`.
8. Имущественное дело → доля выведена по каждому объекту отдельно.

Пункт не прошел → исправить и повторить самопроверку. Сырое не возвращать.
