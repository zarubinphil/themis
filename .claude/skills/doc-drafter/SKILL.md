# Сперанский — составление процессуальных документов

Тяжелое (первичка, практика, позиция) уже сделано агентами — лежит в `01_context/`. Читать кеши, не сырые файлы.

## Токен-дисциплина (на всех шагах)

| Правило | Содержание |
|---|---|
| Один Read на файл | Не читать дважды и не вразбивку. Раздел справочника: `grep -n "^## §"` → ОДИН Read (offset/limit); разделы разбросаны → один Read целиком |
| Кеш роутера | Повторное извлечение запрещено; повторный `markdown_extract.py` = кеш, 0 токенов |
| Механика — в код | Подсчеты, маркеры, сверка реквизитов, поиск «ё» — grep / `python3 -c`, не рассуждением |
| Подача материалов агенту | До 15 000 токенов — ТЕКСТОМ в промпте агента. Путь — только если агент сам решает, что читать, или материал больше |

## Входной контракт (ДО работы; провал → СТОП)

| № | Что | Проверка | Нет → |
|---|---|---|---|
| 1 | Дело | `cases/_index.md` → `cases/{клиент}/{дело}/` | спросить, не угадывать |
| 2 | Карта | `grep -F "## КАРТА ГОТОВА ✓" 01_context/knowledge-map.md` | СТОП → Сбои |
| 3 | Уровень/трек | блок `## ОХОТНИКИ — РЕШЕНИЕ ФЕМИДЫ` в карте; нет → L2 FAST | — |
| 4 | Практика | `grep -E "^## СОВЕТ ЗАВЕРШ" 01_context/practice.md` (маркер в КОНЦЕ файла) | послабления, иначе СТОП |
| 5 | Позиция | `grep -F "СОГЛАСОВАНО СОВЕТОМ" 01_context/positions.md` | послабления, иначе СТОП |

Послабления FAST/L1 (по CLAUDE.md):

| Уровень · трек | practice.md | positions.md |
|---|---|---|
| L1 | файл есть; маркер ИЛИ «FAST-синтез Фемидой» | не требуется |
| L2 FAST | то же | файл есть; маркер ИЛИ «знаю позицию — /position-council пропущен» в `_case.md` |
| L2 FULL / L3 / кассация ВС | только маркер | только маркер; для L3 пропуск запрещен |

Пройден → статус: `✓ Контракт: карта · практика · позиция. Уровень L{X}, трек {FAST|FULL}. Составляю.`

## Алгоритм

### Шаг 1. Redlines (первым, обязателен)

`knowledge/redlines.md` (один Read целиком): раздел категории документа + «Форматирование» + «Общие предпочтения доверителя». Выписать список `- правило → как учту` (обычно 3-7); пусто → «redlines: применимых правил нет». Список не записан → шаг не закрыт.

### Шаг 2. Кеши дела

`knowledge-map.md`, `practice.md`, `positions.md` (по уровню) — по одному Read. К `00_intake/` — только за деталью, которой нет в карте: `python3 scripts/markdown_extract.py FILE --json-meta` → срез из кеша; реквизиты — из готового `<sha>.requisites.json`. Запрещено: intake подряд; `.docx/.pdf/.xlsx` через Read; перераспознавать OCR. Выкладки → `01_context/_working/`, не в чат.

### Шаг 3. Справочники — выборочно по типу документа

Целиком не читать — только разделы `## §N` из таблицы:

| Тип документа | LEGAL_RU_SYSTEM.md | CONTENT_DESIGN.md |
|---|---|---|
| Иск (ГПК/АПК/КАС) | §1, §6 | §1, §2, §4 |
| Отзыв, возражения | §2 | §1, §2 |
| Ходатайство | §3 (+ §6, если облагается) | §1 |
| Апелляция / кассация / надзор | §4, §6 | §1, §2 |
| Семейные дела | §5, §1, §6 | §1, §2, §4 |
| Досудебный (претензия) | §7 | §2, §5 |

Дополнительно: CONTENT §3 — несколько ответчиков или госорган; CONTENT §5 — перед подписью; `DOCX_FORMATTING.md` целиком — перед Шагом 8.
Пошлина: колонка строго по статусу заявителя (физлицо ≠ организация), расчет скриптом, показать в тексте — правило и ставки в LEGAL §6.

### Шаг 4. Позиция

- L2/L3: основа — `positions.md`, адаптировать под тип документа. L1/FAST без него — из карты + practice.md.
- Сужение пакета требований против positions.md — ТОЛЬКО с решением, записанным в positions.md (кто, почему, дата); иначе Кони вернет (урок 23.07.2026).
- Аргументы: каждый вытекает из предыдущего; факты только из карты; каждому доводу оппонента — контрдовод; сильнейший — последним перед просительной частью.
- Доля в имущественных делах — ПО КАЖДОМУ ОБЪЕКТУ отдельно; единая «на все» — только с прямым подтверждением из материалов.

### Шаг 5. Анти-галлюцинация (на всех шагах)

- Каждое правовое утверждение — источник прямо в тексте: `[ст. 333 ГК РФ]`, `[Пленум ВС РФ от ДД.ММ.ГГГГ № X, п. Y]`, `[дело № А65-XXXXX/2024]`. Нет источника → не включать.
  - Хорошо: `Неустойка несоразмерна [ст. 333 ГК РФ; Пленум ВС РФ от 24.03.2016 № 7, п. 71].` Плохо: `Суды обычно снижают неустойку.` — источника нет.
- Реквизиты актов — только из practice.md / hunter-файлов, не из памяти. Не подтверждено → `требует проверки`.
- Цитаты КС РФ / Пленумов — дословно и целиком из `01_context/_practice/hunter_*.md` или первоисточника; купюра только с `[...]`; сжатие по памяти запрещено (урок 23.07.2026, КС № 35-П).
- Ссылки на КС/Пленумы из внешних документов — сверить по ksrf.ru / vsrf.ru ДО заимствования; подмена → предупредить доверителя.

### Шаг 6. Черновик .md

Структура: шапка (суд, № дела, стороны) → факты → правовая позиция (доводы → нормы → практика) → просительная часть → приложения → дата, подпись. Содержание — по разделам CONTENT из Шага 3. Язык — /humanizer: живой официально-деловой; без «ё»; даты ДД.ММ.ГГГГ; понятен неюристу. Сохранить `03_drafts/{документ}_v1.md` (после Кони → `_v2.md`, сквозная нумерация).

### Шаг 7. Guard: правки доверителя (перед сборкой .docx)

Целевой `.docx` уже существует →
1. `cmp -s ФАЙЛ 03_drafts/_baselines/{имя}.docx; echo $?` → `1` = различаются.
2. `officecli get ФАЙЛ.docx /revision` — правки с авторами (первым); фолбэк `unzip -p ФАЙЛ.docx docProps/core.xml | grep -oE "(lastModifiedBy|revision)>[^<]*"`.
3. Правки доверителя → СТОП, не перезаписывать; предложить redline-разбор («изучи мои правки по {дело}»). `save()` дублирует guard (`THEMIS_FORCE_OVERWRITE=1` — только осознанно). Урок 14.07.2026.

### Шаг 8. Сборка .docx — только DocBuilder

ТОЛЬКО `scripts/create_docx.py` (класс DocBuilder). Голый python-docx, шаблоны, ручной XML — запрещены. Выбор метода под ситуацию — DOCX_FORMATTING §2, значения не переизобретать:

```python
from scripts.create_docx import DocBuilder
b = DocBuilder()   # параметры зашиты; методы по DOCX §2: шапка → заголовки → тело → ПРОШУ → приложения → подпись
b.save("cases/.../03_drafts/{документ}_v1.docx")   # авто: «ё»→«е», baseline в _baselines/
```

После `save()` проверить: файл создан И снимок появился в `03_drafts/_baselines/`.

**Код сборки — только внутри дела, никогда в `scripts/`.** Понадобился одноразовый python-файл под конкретный документ — он живет в `cases/{клиент}/{дело}/01_context/_working/`, которая закрыта `.gitignore`. Папка `scripts/` публикуется в открытый репозиторий, а такой файл несет ФИО, адреса, ИНН и суммы доверителя строковыми литералами. Прецедент 02.08.2026: 16 генераторов на 506 КБ с персональными данными пролежали в публичном репозитории, чистились переписыванием истории.

### Шаг 9. Проверка Кони

Запустить `doc-reviewer`: в промпт — ТЕКСТ черновика целиком (правило подачи материалов) + путь к делу + примененные redlines; Кони не перечитывает справочники и кеши. До 2 раундов:
- «ГОТОВ К ПОДАЧЕ» → финализация (Контракт вывода);
- «ТРЕБУЕТ ПРАВОК» → внести → `_v2.md` + `_v2.docx` → повторно;
- «КРИТИЧЕСКИЕ ОШИБКИ» или 2 раунда без одобрения → СТОП, разногласия пользователю списком.

## Контракт вывода

| Артефакт | Путь | Когда |
|---|---|---|
| Черновик | `03_drafts/{документ}_v1.md` | всегда |
| Word | `03_drafts/{документ}_v1.docx` (DocBuilder) | всегда |
| Снимок ДО | `03_drafts/_baselines/{документ}_v1.docx` (кладет `save()`, проверить) | всегда |
| Финал | `02_hearings/ДД-ММ-ГГГГ_название/{документ}.md` + `.docx` | ТОЛЬКО после «ГОТОВ К ПОДАЧЕ» |

Черновики остаются в `03_drafts/`. События нет → `/new-event`; заседание неизвестно → оставить. После финала обновить `_event.md` и `_case.md`. PDF с подписью → `/finalize {docx}`.

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Нет `## КАРТА ГОТОВА ✓` | СТОП: «❌ Карта не готова. Запусти case-mapper» |
| practice.md нет / без маркера (FULL) | СТОП: «❌ practice.md не готов. FAST/L1: охотник + синтез Фемидой; FULL: /askacouncil» |
| positions.md нет / без маркера (L2 FULL, L3) | СТОП: «❌ positions.md не согласован → /position-council» (L2: либо «знаю позицию» в `_case.md`) |
| Деталь/реквизит не подтвержден (карта, кеши, practice/hunter) | не выдумывать: `требует проверки`, при необходимости запросить у доверителя |
| .docx отличается от baseline (Шаг 7) | СТОП, предложить redline-разбор |
| `create_docx.py` упал | сверить с DOCX_FORMATTING, повторить; 2 неудачи → СТОП с ошибкой |
| Кони: критика / нет одобрения | исправить все → `_v2` → повторно; после 2 раундов СТОП: разногласия списком |
| Сузить пакет против positions.md | сначала запись решения в positions.md, потом сужение |

Молчаливая деградация запрещена: любой сбой — фолбэк из таблицы либо СТОП с причиной.

## Самопроверка перед возвратом (по диску, не по памяти)

1. Перечитать сохраненный `.md` с диска (один Read).
2. Выборочно 5 правовых утверждений — у каждого источник `[...]`.
3. Цитаты КС/Пленума дословны (hunter-файлы); купюры только `[...]`.
4. `grep -c "ё" файл.md` → 0; даты только ДД.ММ.ГГГГ.
5. Пошлина: колонка по статусу заявителя, расчет по LEGAL §6 показан.
6. Правила redlines Шага 1 — каждое учтено.
7. `.md` + `.docx` в `03_drafts/`, снимок в `_baselines/`.
8. Имущественное дело → доля по каждому объекту отдельно.

Пункт не прошел → исправить и повторить. Сырое не возвращать.
