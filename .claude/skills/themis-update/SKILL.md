# Обновление Themis

Тянет свежую ЛОГИКУ из GitHub через `scripts/update.sh`, данные пользователя не трогает. Скилл добавляет к скрипту страховку: снимок git-статуса ДО, сверка ПОСЛЕ, откат при сбое.

## Входной контракт

| Проверка | Нет → |
|---|---|
| `.git/` в корне проекта | СТОП: «Не git-клон Themis. Склонируй свежий Themis отдельно и перенеси в него свои `cases/` и `knowledge/` (только их)» |
| `scripts/update.sh` существует | СТОП: система повреждена, сообщить пользователю |

## Что обновляется / что нет

- Обновляется: `.claude/`, `AGENTS.md`, `scripts/`, `cockpit/`, `bin/` (включая `vision-ocr.swift`), `install.sh`, `README.md`, `.mcp.json`, `docs/`. Новые зависимости и пересборка Apple Vision OCR — через `install.sh` (скрипт запускает сам).
- НЕ трогается: `cases/` (все дела), `knowledge/` (practice_index, redlines, lessons-log), рантайм (кеши, `_baselines/`, `cockpit/.state.json`).

## Алгоритм

1. Снимок ДО (вывод каждой команды сохранить в контексте — сверка на шаге 5):

```bash
OLD=$(git rev-parse --short HEAD)
git status --porcelain -- cases knowledge
git status --porcelain -- .claude AGENTS.md scripts cockpit bin install.sh .mcp.json docs
```

2. Третья команда вывела строки (локальные незакоммиченные правки системных путей) → СПРОСИТЬ пользователя: обновление перезапишет их через `git checkout origin -- <путь>`. Без явного «да» — СТОП.
3. `bash scripts/update.sh` — код возврата проверить явно. «Уже последняя версия» → доложить, шаги 4-5 не нужны.
4. Exit ≠ 0 → ОТКАТ: `git checkout "$OLD" -- .claude AGENTS.md scripts cockpit bin install.sh README.md .mcp.json docs` → доложить причину сбоя (последние строки вывода) и факт отката. СТОП.
5. Успех → сверка ПОСЛЕ: повторить `git status --porcelain -- cases knowledge`, сравнить с выводом шага 1. Совпадает → данные целы. Отличается → ЧП: доложить КАЖДОЕ отличие, ничего не удалять и не откатывать данные без решения пользователя.
6. Список обновленного: `git status --porcelain -- .claude AGENTS.md scripts cockpit bin docs | head -20`.

## Контракт вывода

Ответ пользователю (не файл): версия ДО → ПОСЛЕ (или «уже последняя»), список обновленного (до 15 строк), строка о целости данных, пересборка OCR если была (скрипт печатает).

- Хорошо: «✓ Обновлено 3f2a1c9 → 8d4e7b2: .claude/agents (3 файла), scripts/markdown_extract.py. OCR пересобран. Данные дел (cases/) и база знаний (knowledge/) целы ✓»
- Плохо: «Обновление выполнено успешно» (без версий, списка и подтверждения целости данных).

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Не git-клон | СТОП + инструкция: свежий клон, перенести `cases/` + `knowledge/` |
| `git fetch` упал (нет сети) | Скрипт завершится ошибкой до правок → доложить «нет связи с GitHub, повтори позже», откат не нужен |
| `install.sh` упал после checkout | Откат по шагу 4 + последние строки лога ошибки в доклад |
| Локальные правки системных файлов | СПРОСИТЬ до запуска — не терять молча |
| Сверка данных ПОСЛЕ показала отличия | ЧП: доложить каждое отличие, данные не трогать |

## Самопроверка перед возвратом

- [ ] Снимок ДО снят до запуска update.sh
- [ ] Код возврата update.sh проверен явно, не по общему виду вывода
- [ ] Сверка `cases/` + `knowledge/` выполнена по диску (сравнение снимков), результат в докладе
- [ ] В докладе обе версии (ДО → ПОСЛЕ) либо «уже последняя»
- [ ] При сбое — откат выполнен и об этом сказано прямо
