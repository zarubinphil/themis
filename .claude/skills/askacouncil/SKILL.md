# Роль

Совет по судебной практике. Один охотник может ошибиться — три охотника под перекрестным допросом не могут. Никакой живой дискуссии: один структурированный раунд анонимного рецензирования, затем синтез председателя.

## Состав, модели, раунды

| Участник | Модель (Agent tool) | Задача |
|---|---|---|
| Рецензенты 1-3, параллельно | `sonnet` (Sonnet 4.6) | оценка анонимизированных отчетов |
| Председатель | `opus` (Opus 4.8) | деанонимизированный синтез, вердикт |
| Исполнитель скилла (Фемида) | текущая сессия | анонимизация, верификация цифр, запись practice.md и файлов аудита |

Раунд рецензирования ровно один. Расхождение рецензентов — не сбой и не повод для второго раунда: решает председатель (шаг 5). Итоговый practice.md пишет исполнитель скилла на основе вердикта председателя.

## Входной контракт

Проверить ДО запуска. Любой пункт не выполнен → СТОП с текстом из третьей колонки, совет не начинать.

| Условие | Проверка | Нет → СТОП с текстом |
|---|---|---|
| Трек FULL (спорный L2 / L3) | триаж и уровень в `_case.md` | «L1 и FAST — совет не запускается, синтез practice.md делает Фемида сама (Opus)» |
| Три отчета охотников | `ls 01_context/_practice/hunter_{classic,skeptic,tactical}.md` | «Запустите охотника {имя отсутствующего}» |
| В каждом ≥3 источника с номерами дел | grep по `№` и датам в каждом hunter-файле | перезапустить этого охотника (до 2 раз), после — СТОП |
| Карта дела | `grep '## КАРТА ГОТОВА ✓' 01_context/knowledge-map.md` | «Запустите case-mapper» |
| Вопросы не закрыты ранее | заголовки разделов существующего practice.md | закрытые вопросы исключить из повестки; все закрыты → СТОП: «практика уже закрыта, совет не нужен» |

## Алгоритм

### Шаг 1. Контекст и вопрос совета

Прочитать по одному разу (повторно не перечитывать): `knowledge-map.md`, `_case.md`, три `hunter_*.md`. Сформулировать нейтральный вопрос совета — без пересказа отчетов:

```
Три независимых аналитика исследовали судебную практику по делу {клиент} / {дело}.
ПРАВОВЫЕ ВОПРОСЫ: {список из knowledge-map.md, только незакрытые}
КОНТЕКСТ: {стороны, суть, кодекс — 2-3 строки из _case.md}
НА КОНУ: {какой документ готовится / стадия}
Задача совета: оценить надежность практики, выявить пробелы и противоречия, дать базу для синтеза.
```

### Шаг 2. Анонимизация (утечка по стилю — реальный инцидент, см. knowledge/lessons-log.md 23.07.2026)

1. Случайно назначить отчетам буквы А/Б/В.
2. Подготовить тексты для рецензентов: снять первый заголовок каждого hunter-файла и все самоназвания охотников (Спасович, Плевако, Классик, Скептик, Тактик, «охотник А/Б/В»), заменить шапку на «Отчет {буква}».
3. Контроль утечки перед раздачей: `grep -icE "спасович|плевако|классик|скептик|тактик" {анонимизированный текст}` — нашлось → дочистить, только потом раздавать.
4. Маппинг букв записать СРАЗУ (до запуска рецензентов) в шапку `01_context/_council/council_reviews.md`. Рецензентам маппинг не раскрывать.

### Шаг 3. Рецензирование — 3 субагента параллельно, одним сообщением, model: sonnet

Каждый рецензент получает вопрос совета + три анонимизированных отчета целиком в промпте (пути к файлам не давать — сырье не перечитывать). Промпт:

```
Ты — старший юрист, рецензируешь работу трех аналитиков судебной практики.
{вопрос совета}
Отчет А: {текст} / Отчет Б: {текст} / Отчет В: {текст}

Правило (дословно, обязательное): стиль отчета не является основанием атрибуции.
Оценивай только содержание — источники, полноту, применимость. Попытка угадать
автора по манере письма — ошибка рецензии.

Ответь тремя пунктами, ссылаясь на отчеты по буквам, до 250 слов, без дипломатии:
1. СИЛЬНЕЙШИЙ ОТЧЕТ (один): почему, что выгодно отличает.
2. СЛАБОЕ МЕСТО (один отчет): что пропустил или сделал неверно.
3. ОБЩИЙ ПРОБЕЛ: чего не хватает всем трем — вопрос, угроза, источник.
```

Ждать все три ответа. Один упал/пустой → перезапустить только его (до 2 раз), после двух неудач → СТОП, доложить.

### Шаг 4. Верификация замечаний рецензентов (замечания тоже врут)

Каждое критическое замечание о цифрах — госпошлина, сроки, суммы, реквизиты актов — исполнитель сверяет по первоисточнику ДО передачи председателю: сначала `knowledge/practice_index.md` (grep), затем sgai/Firecrawl по vsrf.ru / ksrf.ru / kad.arbitr.ru. Бывают ложные тревоги (пошлина физлица vs организации). Итог пометить в council_reviews.md: `подтверждено` / `отклонено: {причина}` / `требует проверки`. Непроверяемое в вердикт входит только как «требует проверки».

### Шаг 5. Председатель — 1 субагент, model: opus

Получает: вопрос совета, три отчета С РАСКРЫТЫМИ именами (Классик/Скептик/Тактик), три рецензии с пометками верификации. Структура вердикта — строго:

```
## Где охотники сходятся          — подтверждено 2-3 охотниками, высоконадежное
## Где охотники расходятся        — реальные противоречия, не сглаживать, влияние на дело
## Слепые пятна рецензентов       — что вскрылось только перекрестным анализом
## Уровни надежности практики     — каждый акт: Уровень 1 (2-3 источника) /
                                    Уровень 2 (один, не оспорен) / Уровень 3 (спорный)
## Итоговая рекомендация          — прямо: ссылаться на X, контрдовод на Y, Z не использовать
## Первый шаг                     — одно действие прямо сейчас
```

Правила председателя: может не согласиться с большинством рецензентов — следует сильному аргументу, не голосованию; реквизиты не выдумывать, неподтвержденное — «требует проверки»; цитаты Пленума/КС — дословно из hunter-файлов или не цитировать.

### Шаг 6. Запись артефактов (исполнитель)

1. `01_context/_council/council_reviews.md` — маппинг (из шага 2) + три рецензии + пометки верификации.
2. `01_context/_council/council_verdict.md` — вердикт председателя полностью.
3. `practice.md` — инкрементально: разделы по закрытым ранее вопросам не перезаписывать, новые добавить, устаревшие обновить с пометкой даты.
4. Рапорт в чат — caveman, 3-5 строк. Большие тексты в чат не выводить. Собрать `usage` всех субагентов для токен-отчета Фемиды.

## Контракт вывода

Путь: `cases/{client}/{case}/01_context/practice.md`. Обязательные разделы:

```
# Судебная практика — {Клиент} / {Дело}
Обновлено: ДД.ММ.ГГГГ
## СОВЕТ ЗАВЕРШЕН — ДД.ММ.ГГГГ ✓
Охотники: Классик ✓ | Скептик ✓ | Тактик ✓ · Рецензентов: 3 · Раундов: 1
## Практика в нашу пользу — Уровень 1 (Подтверждено)
## Практика в нашу пользу — Уровень 2 (Один источник)      ← «проверить реквизиты перед ссылкой»
## Практика против нас — для контраргументов               ← довод / практика / наш ответ
## Процессуальная практика                                 ← сроки, доказательства, подсудность
## Спорные позиции — Уровень 3                             ← таблица: вопрос / позиция А / позиция Б / рекомендация
## Слепые пятна (нужна дополнительная работа)              ← чекбоксы: что не нашли — что сделать
## Источники                                               ← таблица: акт / реквизиты / URL / уровень / охотник
```

Каждый акт: `Постановление {суд} от ДД.ММ.ГГГГ № {номер}` + суть + как использовать. Маркер завершения — дословно `## СОВЕТ ЗАВЕРШЕН` (канон: слово ЗАВЕРШЕН пишется через Е; строка с датой после маркера допустима).

Хорошо: `Определение СКГД ВС РФ от 14.02.2023 № 5-КГ22-144-К2 — срок давности по разделу течет с момента нарушения права, не с развода. Использовать против довода о пропуске срока.`
Плохо: `Суды обычно поддерживают такую позицию` — нет реквизитов, в practice.md не включать.

## Сбои: ситуация → действие

| Ситуация | Действие |
|---|---|
| Нет hunter-файла / нет маркера карты | СТОП, текст из входного контракта |
| В hunter-файле <3 источников | перезапуск этого охотника (до 2), после — СТОП |
| Рецензент упал / вернул пусто | перезапуск только его (до 2), после — СТОП с докладом |
| Grep нашел имя охотника в анонимном тексте | дочистить, рецензентов до чистки не запускать |
| Рецензент атрибутировал отчет по стилю | атрибуцию игнорировать, содержание рецензии использовать |
| Замечание о цифрах не подтвердилось | пометить «отклонено» в council_reviews.md, председателю передать с пометкой |
| Источник не верифицируется | «требует проверки» — не выдумывать, archivist такие записи не индексирует |
| `Agent type ... not found` | СТОП: реестр стар, полный перезапуск Claude Code (не resume) |
| Вопрос уже закрыт в practice.md | не пересоветовать, исключить из повестки |

## Самопроверка перед возвратом (по диску, не по памяти)

- [ ] `practice.md` перечитан с диска, маркер `## СОВЕТ ЗАВЕРШЕН` присутствует дословно
- [ ] Каждый акт имеет реквизиты формата `{суд} от ДД.ММ.ГГГГ № {номер}` либо пометку «требует проверки»
- [ ] Все даты ДД.ММ.ГГГГ; запрещенная буква отсутствует: `grep -n $'\u0451\|\u0401' {файл}` — пусто
- [ ] `council_reviews.md`: маппинг + 3 рецензии + пометки верификации на месте
- [ ] `council_verdict.md` записан полностью
- [ ] Ранее закрытые разделы practice.md не затерты (сверить заголовки со старой версией)
- [ ] Таблица «Источники» согласована с разделами (ни одного акта без строки в таблице)

Не прошло — исправить и перепроверить, сырое не возвращать.
