## 2. Главный дефект: накладные расходы на чтение файлов ×3-6

**Замер.** Роль Ареопага в раунде 1 получала три файла: `knowledge-map.md` (18 050 токенов), `practice.md` (9 770), `council_verdict.md` (12 380). Итого вход — **40 200 токенов**. Фактическая цена вызова — **около 130 000**. Накладные — **×3,2**.

**Механика.** Я передавал роли не текст, а пути к файлам, чтобы не раздувать собственный контекст. Роль делала 3-4 вызова Read подряд. При каждом вызове инструмента весь накопленный контекст отправляется заново:

```
старт (системный промпт + задание)         ~5 000
Read карты          → отправлено  5 000 + 18 050 = 23 050
Read практики       → отправлено 23 050 +  9 770 = 32 820
Read вердикта       → отправлено 32 820 + 12 380 = 45 200
Write результата    → отправлено 45 200 + вывод  ≈ 48 000
                                    ИТОГО ≈ 154 000
```

Расчет сходится с фактом. **Каждый лишний Read удваивает стоимость роли.** У рецензентов совета накладные оказались еще выше — ×5,7 (вход 22 000, факт 125 000 при трех Read).

**Вывод.** Дорого обходится не объем материалов, а число обращений к ним. Это самый крупный и самый дешевый в устранении дефект прогона.

## 3. Разбор по этапам: что было лишним

### 3.1 Охота — 1 027 878 токенов (самая дорогая статья)

| Что | Токены | Оценка |
|---|---|---|
| Классик, первый круг | 160 654 | оправдано |
| Классик, доверификация 4 актов | 243 605 | **завышено ×40** — см. ниже |
| Скептик | 153 449 | оправдано, дал две критичные угрозы |
| Тактик, первый круг | 220 220 | оправдано |
| Тактик, добор через Tavily | 249 950 | **полностью впустую** |

**Дефект 1. Верификацию актов делал LLM вместо кода.** Классик потратил 243 605 токенов, чтобы подтвердить четыре судебных акта по первоисточнику. Я позже сделал ровно то же самое для двух актов (№ 5-КГ22-82-К2 и № 81-КГ19-2) через `scripts/fetch_url.sh` плюс `python3` с регулярками — расход около **6 000 токенов на акт**, и результат оказался точнее: именно скриптовая проверка вскрыла, что 13.06.2019 — дата публикации, а не дата акта.

Верификация реквизита — механическая операция: скачать страницу, найти номер, дату, состав коллегии, ключевую формулировку. LLM тут нужен только чтобы прочитать итог «подтверждено / не найдено».

**Дефект 2. Добор запущен вслепую.** Я поручил Тактику искать через Tavily MCP, не проверив ни набор его прав, ни наличие ключа. Агент честно прошел шесть каналов и вернул «инструмент недоступен». Цена проверки, которую я не сделал: одна команда `grep tavily $HOME/.claude.json`. Цена ошибки: 249 950 токенов.

**Дефект 3. Квота WebSearch не проверялась до старта.** Тактик обнаружил исчерпание лимита (200/200) уже в процессе, потратив на это часть прогона. Проверка квоты — условие входа в шаг 2, а не открытие по ходу.

### 3.3 Совет по практике — 554 266 токенов

Три рецензента по 125 000 каждый ради ответа в 250 слов. Накладные ×5,7. При этом ценность высокая: единогласно вскрыт непроработанный правовой вопрос (доход против прибыли ИП), отсеяна ложная тревога по дате акта.

Лишнее: рецензенты читали hunter-файлы целиком (540 строк), включая разделы «Не найдено» и «Ограничения поиска», которые для оценки надежности практики не нужны. Достаточно разделов «Найдено» и «Источники» — это примерно 40 % объема.

### 3.4 Архивариус — 108 448 токенов на четыре записи

Агент читал `practice.md` целиком и `practice_index.md` (912 строк), чтобы найти место вставки и сверить дубликаты. Итог работы — четыре абзаца текста по готовому шаблону.

Дешевле: Фемида формирует готовые блоки записей (она уже держит их в контексте после синтеза `practice.md`), архивариус только проверяет дубликаты грепом и вставляет. Оценка — около 30 000 вместо 108 448.

### 3.5 Основной поток — 450 000 токенов

Мои собственные потери:

Оправданные расходы основного потока: верификация актов скриптами, сверка счетов по OCR (закрыла блокер Б4 и усилила позицию), разбор арифметики конвертации валют (превратил ложную тревогу в довод).

## 4. Где MCP не помог бы, а где помог бы

Честный ответ: **основная экономия лежит не в MCP, а в переносе механики из LLM в локальный код.** Разбор по доступным серверам:

| Инструмент | Применимость к делу | Вердикт |
|---|---|---|
| `markitdown` MCP | извлечение текста из документов | **не нужен**: `scripts/markdown_extract.py` делает то же плюс кеш, плюс OCR, плюс автоизвлечение реквизитов. Замена ухудшила бы результат |
| `memory` MCP | хранение верифицированных актов между делами | **частично**: сейчас эту роль выполняет `knowledge/practice_index.md` — файл дешевле и прозрачнее. Плюс MCP был бы в семантическом поиске по 101 записи, но выигрыш не окупает усложнения |
| `playwright` MCP | обход сайтов судов, когда curl режется | **да, точечно**: реальная альтернатива для vsrf.ru, который не отдавался ни прямым запросом, ни через Jina Reader. Но тяжелый — держать как фолбэк третьего уровня, не как основной путь |
| `tavily` | веб-поиск при исчерпанном WebSearch | **потенциально да**, но сервер без ключа и недоступен агентам с явным списком `tools` |
| `context7` | документация библиотек | не применим к юридическим делам |
| `github` | репозитории | не применим |

**Главный вывод.** В этом конвейере уже есть локальные инструменты стоимостью ноль: Apple Vision OCR (194 страницы бесплатно), `markdown_extract.py` с кешем, `fetch_url.sh`, `themis_status.py`. Проблема не в отсутствии MCP, а в том, что **работу этих инструментов дублировал LLM**: охотники искали и верифицировали токенами то, что скрипт делает даром.

## 6. Конкретные правки, по приоритету

1. **Правило подачи материалов агенту** (`.claude/CLAUDE.md`, раздел о рое). «Материалы объемом до 15 000 токенов подавать агенту текстом прямо в промпте, а не путями к файлам. Каждый Read внутри агента переотправляет весь накопленный контекст и удваивает стоимость вызова. Пути давать только когда агент сам выбирает, что читать (case-mapper, охотники), либо когда материал больше 15 000 токенов». Ожидаемый эффект — минус 30-50 % на всех советах.

2. **Верификацию судебных актов вынести в скрипт.** Новый `scripts/verify_act.py`: на вход список реквизитов, на выход таблица «подтверждено / не найдено / расхождение» с цитатой. Внутри — `fetch_url.sh` плюс регулярки по номеру, дате, составу коллегии. Охотник отдает список, скрипт проверяет, LLM читает итог. Минус около 240 000 на прогон, плюс рост точности.

3. **Preflight каналов поиска перед шагом 2.** Одна команда: квота WebSearch, баланс ScrapeGraphAI, наличие ключа Tavily, доступность Firecrawl. Результат — в промпт охотникам явным списком «доступно / недоступно». Минус 250 000 на прогон.

4. **Бриф вместо полного контекста для советов.** Фемида один раз собирает `_council/brief.md` (фактура, вопросы, уровень 1 практики — около 12 000 токенов) и подает его текстом всем ролям. Минус 60-70 % на Ареопаге.

5. **Модели.** В раунде 1 Ареопага все роли — Sonnet, включая Тактика. Opus остается на синтезе, председательстве и спорной верификации.

6. **Дисциплина основного потока.** Не читать hunter-файлы и отчеты роя целиком: сводки в уведомлениях о завершении агентов содержат достаточно. Читать файл один раз, нужным диапазоном.

## 7. Что в прогоне было сделано правильно и менять не нужно

- **Локальный OCR.** 194 страницы через Apple Vision — ноль стоимости, ни одного обращения к облачному vision на основном проходе.
- **Кеш роутера.** Шесть файлов с прогретым кешем не переизвлекались, реквизиты брались из готового `<sha>.requisites.json`.
- **Скриптовая верификация в основном потоке.** Проверка счетов Альфа-Банка по OCR закрыла блокер Б4 и превратила риск двойного учета в рабочий довод — ценой около 3 000 токенов.
- **Разбор арифметики конвертации.** Ложная тревога о необоснованности сумм на 20,5 млн руб. снята сверкой Таблиц 82-83 и пересчетом по курсу — ценой около 5 000 токенов.
- **Машина состояний.** Пять вызовов `themis_status.py` по цене вывода в 8 строк удержали порядок шагов и позволили остановиться без потери прогресса.
- **Отказ подделать маркер Кони.** Шаг 5 остался незакрытым честно.
