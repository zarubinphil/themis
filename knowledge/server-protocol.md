# Протокол сервера Фемиды

Этап 6 плана перестройки. Здесь — что и как работает на серверной стороне, что делает
владелец руками и почему именно так. Значения секретов в этом файле не приводятся
никогда: только имена переменных и места хранения.

## Что вообще уходит на сервер

| Уходит | Не уходит никогда |
|---|---|
| Извлечённый текст дела (`.md`, `.txt`, `.json`) | Оригиналы из `00_intake` — сканы, договоры, фото |
| Карты, практика, позиции, черновики в `.md` | Рендеры страниц и любые картинки |
| Готовый `.docx` режима 2 | Подписанный PDF (собирается только на Маке) |

Границу держит `scripts/sync_receiver.py`, а не договорённость: он смотрит на сам файл
и отвергает оригинал, бинарник под текстовым именем, симлинк и путь вне очереди.
Проверка: `python3 scripts/sync_receiver.py --selftest`.

**Результат режима 2 на сервере — `.docx`** (решение владельца 18.08.2026). Подпись и
сборка PDF остаются на Маке: `sign_and_pdf.py` идёт через Word и AppleScript, способ
подписи на Linux не разрабатывается. Сервер отдаёт документ, Мак его подписывает.

## Отдельный непривилегированный пользователь

Фемида на сервере работает от собственного пользователя без прав администратора:

- отдельный системный пользователь `themis`, без `sudo`, с домашним каталогом только
  под свои данные;
- каталог очереди синхронизации принадлежит ему и закрыт для остальных (`chmod 700`);
- панель запускается этим же пользователем и слушает **только петлю** (`127.0.0.1`),
  наружу выходит через обратный прокси с TLS;
- Claude Code на сервере авторизован под этим пользователем, своей учётной записью,
  не копией авторизации Мака.

Смысл: взлом панели даёт права на выжимки дел, но не на сервер и не на чужие сервисы.

## Секрет панели: перезагрузка, отзыв, восстановление

Секрет живёт в `~/.secrets/themis-panel.env` (`chmod 600`), переменная
`THEMIS_PANEL_TOKEN`. В коде и в git — только имя переменной.

- **Перезагрузка** (плановая смена): записать новое значение в файл секретов,
  перезапустить панель, открыть `https://…/login?token=НОВЫЙ` в браузере — cookie
  сменится. Старые cookie перестают действовать сразу: сверка идёт с текущим значением.
- **Отзыв** (утечка, потерянный ноутбук): стереть значение из файла и перезапустить
  панель. Без секрета панель не станет слушать не-петлевой интерфейс — то есть
  выключается сама, а не остаётся открытой. Затем выдать новое значение по правилу
  перезагрузки.
- **Восстановление** (секрет забыт): значение восстановлению не подлежит и не хранится
  нигде, кроме файла секретов. Порядок — зайти на сервер по SSH, записать новое,
  перезапустить панель.
- Секрет не печатается в логи: журнал доступа пишет маршрут, адрес и исход, но не
  заголовки. Проверяется приёмкой этапа (`scripts/stage6_spec.py`).

Ключ SSH к серверу — отдельная сущность, живёт в `~/.ssh` и в Keychain, к панели
отношения не имеет; его ротация делается по тому же порядку: новый ключ в
`authorized_keys`, проверка входа, удаление старого.

## Открытый DNS-резолвер

На сервере обнаружен открытый рекурсивный резолвер: он отвечает на запросы из
интернета и потому годится для усиления DDoS-атак чужими руками. Закрыть:

- слушать только петлю и внутренний интерфейс, не `0.0.0.0`;
- рекурсию разрешить только своим подсетям;
- проверить снаружи, что порт 53 (UDP и TCP) не отвечает на чужой запрос.

Действие выполняется на сервере владельцем: это изменение наружу, автономно оно
не делается.

## Ограничение частоты и журнал доступа

- Порог — `THEMIS_RATE_LIMIT` запросов в минуту на клиента (по умолчанию 60),
  перебор даёт 429 без выполнения работы.
- Журнал — `THEMIS_ACCESS_LOG` (по умолчанию `access.log` в корне проекта):
  время, метод, маршрут, адрес, исход (`ok` / `401` / `429`). Содержимого запроса
  и персональных данных там нет: журнал доступа читают чаще, чем дела.

## Порядок выкатки (делает владелец)

1. Завести пользователя `themis`, каталог очереди `chmod 700`.
2. Положить `~/.secrets/themis-panel.env`, `chmod 600`, значение — новое, не с Мака.
3. Запустить панель под этим пользователем на `127.0.0.1`, наружу — прокси с TLS.
4. Закрыть открытый DNS-резолвер, проверить снаружи.
5. Прогнать приёмку этапа на сервере: `python3 scripts/stage6_spec.py`.
6. Проверить руками: анонимный запрос к `/api/run` даёт 401, `/login?token=…` пускает.
