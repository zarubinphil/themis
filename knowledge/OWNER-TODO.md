  второго рубежа сторожа. Реальных данных в этих строках нет;
- адрес клонирования в README цел: фамилия владельца в `github.com/<handle>` —
  публичный бренд, а не тайна доверителя, и под замену не идёт;
- состав файлов совпадает с боевым: 264 файла, `cases/` — 8 служебных.

Полная копия ДО чистки: `/tmp/themis-publish/backup/themis-before-cleanup.bundle`
(проверена `git bundle verify`, «records a complete history»). Незакоммиченная
работа параллельной сессии сохранена патчем там же.

**Почему не опубликовано.** Публикацию блокирует ваш собственный глобальный
сторож `~/.claude/hooks/bash-guard.sh`: «force-push в main/master — необратимо
для общей истории, делай через PR». Сторож прав, и обходить его я не стал.
Публикация — ваше решение и ваша рука.

Порядок публикации (выполнять ВАМ, у агента блокирует сторож):

1. сохранить незакоммиченное в боевом репозитории — там работала другая сессия:
   `git -C ~/Проекты/themis stash -u`
2. опубликовать очищенную историю из `/tmp/themis-publish/clean` в `origin`,
   ветка `main`, с `--force-with-lease` (не с голым `--force`: при чужой правке
   наверху команда обязана отказать, а не переписать молча);
3. подтянуть переписанную историю в боевой репозиторий:
   `git -C ~/Проекты/themis fetch origin`, затем
   `git -C ~/Проекты/themis reset --hard origin/main`, затем `git stash pop`.

Честная оговорка: замена истории на GitHub не стирает её из форков, зеркал и
кеша GitHub. Гарантии «нигде не осталось» нет — есть снятие публичной
доступности. Те 15 объектов лежат в открытом доступе с 23.06.2026.

Если каталог `/tmp` очищен, чистка воспроизводится: клон боевого репозитория →
`git_filter_repo.py --replace-text` (латинские имена папок; стем владельца,
входящий в адрес репозитория, исключён) → `--replace-message` буквальными
строками (кириллические регулярки в filter-repo не работают: сопоставление
байтовое) → повторный аудит до нуля имён.
